## 1. 测试概述

### 1.1 目的

验证本轮改造后的 JPBX 平台在 **JDK 21 + Spring Boot 2.5.15 + Shiro 1.13** 环境下可正常打包、启动与运行；18 个 PBX 业务模块与系统管理功能可用；`mod_xml_curl` 动态配置、ESL 热生效与 CDR 落库链路完整；同时验收浅色专业风界面、品牌 Logo 与去若依改造结果。

### 1.2 范围

| 范围 | 内容 |
| --- | --- |
| 构建与启动 | Maven 全模块打包、JDK 21 运行时、启动脚本、ESL 连接 |
| 业务模块 | 呼叫账户、SIP 域名、分机分组、网关、拨号方案、路由、IVR、队列、坐席、Tier、会议室、语音留言、ACL、系统参数、FS 参数、实时运维、通话记录、录音、日志（18 项） |
| 系统管理 | 用户、角色、菜单、部门、参数、公告、服务监控、代码生成 |
| 集成 | xml_curl 三类配置段、非法 token、ESL API、callcenter 热生效、CDR 落库 |
| 界面 | 登录页、主框架、首页概览、列表页、表单弹窗、锁屏、错误页、Logo/favicon、去若依 |

### 1.3 结论摘要

- **构建**：7 个模块在 JDK 21 下 `clean package` 成功，Spring Boot repackage 正常（ASM 9.7 覆盖生效）。
- **运行**：应用在 JDK 21.0.7 启动成功，ESL 已连接（8021），首页概览读取到实时注册数、账户数、网关数。
- **接口**：xml_curl `directory` / `dialplan` / `configuration` 三段均返回合法 XML；非法 token 返回 not-found。
- **业务**：呼叫账户新增/查询/修改/删除全链路通过；队列 + 坐席 + Tier 写入后 `reloadxml` 生效于 FreeSWITCH，删除后同步移除；队列导出接口返回文件。
- **话务**：`loopback/1132` 测试呼叫产生 2 条 CDR 并成功写入 `youpbx.cdr`，通话记录页面可查询。
- **界面**：全部页面渲染正常（HTTP 200），浅色专业风、Logo、favicon 生效；`src/main` 内 `ruoyi|若依` 命中数 **0**。

> 说明：本机无可用的 SIP 软电话，**真实分机注册**由外部终端完成，报告中标注为「待外部终端验证」并给出验证命令，其余链路均已实测。

## 5. 集成测试

### 5.1 mod_xml_curl

请求：`POST http://localhost:8090/pbx/api/xml`，`token=jpbx-xml-curl-token`。

| 段 | 参数 | 返回 | 结果 |
| --- | --- | --- | --- |
| directory | `section=directory&user=1132&domain=192.168.0.118` | `<document type="freeswitch/xml"><section name="directory">…` | 通过 |
| dialplan | `section=dialplan&Caller-Context=default` | 含 `1132` 分机 extension 的 dialplan XML | 通过 |
| configuration | `section=configuration&key_value=sofia.conf` | sofia profile 配置 | 通过 |
| configuration | `key_value=callcenter.conf` | queue/agent/tier 节点随数据变化 | 通过 |
| configuration | `key_value=cdr_pg_csv.conf` | `db-info` 取自系统参数（cdr_db_info） | 通过 |
| 安全 | `token=bad` | 返回 `result status="not found"` | 通过 |

### 5.2 ESL 与热生效

```text
freeswitch@internal> status
FreeSWITCH (Version 1.11.0 64bit) is ready
UP 0 years, 0 days, 11 hours, 11 minutes

freeswitch@internal> callcenter_config queue list
name|strategy|moh_sound|time_base_score|…
test_queue|longest-idle-agent|…        ← 由 JPBX 配置 + reloadxml 生成
```

应用侧「热生效」返回最后一次执行记录：`reloadxml` + `reload mod_callcenter` 均执行成功。

### 5.3 CDR 落库

1. 通过系统参数 `cdr_db_info` 下发 `cdr_pg_csv.conf`（`dbname=youpbx`）；
2. `reload mod_cdr_pg_csv` 后执行 `originate loopback/1132/default &park`；
3. 查询 `youpbx.cdr`：

| caller_id_number | destination_number | billsec | hangup_cause | start_stamp |
| --- | --- | --- | --- | --- |
| 1000 | 1132 | 2 | NORMAL_CLEARING | 2026-11-19 10:37:26 |
| default | 1132 | 2 | NORMAL_CLEARING | 2026-11-19 10:37:26 |

结论：FreeSWITCH → PostgreSQL → JPBX 通话记录页面 全链路打通。

## 8. 缺陷与遗留

| 编号 | 级别 | 描述 | 处理 |
| --- | --- | --- | --- |
| D-01 | 中 | 启动脚本此前为 LF 换行，Windows `cmd` 无法解析（报「系统找不到指定的路径」） | 已统一转为 CRLF，`start-jpbx.bat` 启停/状态正常 |
| D-02 | 中 | `cdr_pg_csv.conf` 模板默认密码为 `postgres`，与本机实例不一致导致 CDR 写入失败并落 spool | 通过系统参数 `cdr_db_info` 下发正确连接串后恢复；建议安装文档强调该项 |
| D-03 | 低 | 删除坐席后 FreeSWITCH 运行时对象仍保留，需 `reload mod_callcenter` 或 `callcenter_config agent del` | 已在报告注明；后续版本可在删除后显式调用 `agent del` |
| D-04 | 低 | 会议室页面无搜索区，与其他列表页版式略有差异 | 视觉可接受，后续统一 |
| D-05 | — | 本机无 SIP 软电话，真实注册/呼入呼出未实测 | 待外部终端验证，步骤见 5.4 |
| D-06 | — | 测试期关闭验证码（`--shiro.user.captchaEnabled=false`） | 生产保持开启，登录页验证码区域渲染正常 |
