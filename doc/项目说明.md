## 1. 项目是什么

**JPBX** 是一套用 Java Web 管理 **FreeSWITCH 1.11** 的图形界面。管理员在浏览器中配置分机、中继、拨号规则、IVR、队列等；系统把配置存在 **PostgreSQL**，FreeSWITCH 通过 **mod_xml_curl** 向 JPBX 拉取 XML，配置变更通过 **ESL** 热加载，一般不必重启交换机。

### 1.1 解决什么问题

| 痛点 | JPBX 做法 |
|------|-----------|
| 手改 `conf/*.xml` 易错、难审计 | Web 表单 + 参数说明/示例 + 校验 |
| 改完要重启 FS，业务中断 | ESL 热生效（reloadxml / sofia rescan 等） |
| 拨号逻辑散落在 ESL 脚本 | 标准 dialplan，由 FS 执行 |
| 运维缺少可视化 | 通道、注册、Sofia、模块、日志、录音、CDR |

### 1.2 非目标

- 不是 FusionPBX 的完整克隆，但覆盖主流 PBX 管理能力。
- 不替代 FreeSWITCH 本机安装与模块编译。
- 不把敏感口令硬编码进仓库（生产请改 `application-druid.yml` / `fs.properties`）。

## 2. 角色与使用场景

| 角色 | 典型工作 | 主要菜单 |
|------|----------|----------|
| 产品 / 设计 | 理解菜单信息架构、配置项说明与校验提示 | 全部业务菜单、FS 参数配置页 |
| 后端开发 | 加实体/API/热生效/xml 模板 | `jpbx-gui` 模块 |
| 前端（业务页） | Thymeleaf 列表/表单、校验展示 | `templates/pbx/**` |
| 运维实施 | 装库、对接 FS、联调 | 本文第 6 节 + [FreeSWITCH对接与安装说明.md](FreeSWITCH对接与安装说明.md) |

### 2.1 一条完整业务路径（设计可对照）

```
管理员登录 JPBX
  → 配置域名、分机、网关、拨号计划 / FS 参数
  → 点击保存（系统写库 + ESL 热生效）
  → 话机注册：FS 向 /pbx/api/xml?section=directory 拉用户
  → 用户拨号：FS 向 section=dialplan 拉取规则并执行
  → 通话结束：CDR 入库，录音落盘，可在「通话记录/录音」查看
```

## 3. 功能模块说明（设计 + 开发对照）

### 3.1 菜单信息架构

一级菜单：**PBX管理**（`menu_id` 段 2100–2199）。下面按「查看 / 配置」拆分，配置再按业务归类；分组菜单 `menu_id` 为 2130–2134。

| 分组 | 菜单 | URL | 权限前缀 | 业务含义 |
|------|------|-----|----------|----------|

| 运行查看（只读） | 通话记录 | `/pbx/call/view` | `pbx:call:*` | CDR |
| 运行查看（只读） | 录音管理 | `/pbx/record` | `pbx:record:*` | 录音文件浏览下载 |
| 运行查看（只读） | FS日志 | `/pbx/log/view` | `pbx:log:*` | 日志查看 |
| 运行查看（只读） | 呼叫流程看板 | `/pbx/flow` | `pbx:flow:*` | ACL → 路由 → 拨号计划 → 目的地 可视化与号码路径模拟 |

| 分机与账号 | SIP域名 | `/pbx/domain` | `pbx:domain:*` | directory 中的 domain |
| 分机与账号 | 分机组 | `/pbx/group` | `pbx:group:*` | 分机组 / 寻线组指针 |
| 分机与账号 | 语音留言 | `/pbx/voicemail` | `pbx:voicemail:*` | 留言元数据 |
| 路由与网关 | 中继网关 | `/pbx/gateway` | `pbx:gateway:*` | sofia gateway |

| 呼叫应用 | IVR菜单 | `/pbx/ivr` | `pbx:ivr:*` | 语音导航 |

| 系统设置 | **FS参数配置** | `/pbx/fsconf` | `pbx:fsconf:*` | 按参数名/值管理 FS conf（推荐） |

已有库升级执行 `sql/upgrade_pbx_menu_groups.sql`；脚本幂等，会自动补齐分组菜单和角色授权。

### 3.1.1 呼叫流程看板

`/pbx/flow` 为只读看板，数据由 `CallFlowBoardService` 装配，复用 xml_curl 的取数与 `RouteDialplanCompiler`，保证展示的匹配表达式/动作与 FreeSWITCH 实际下发的 dialplan 一致。看板按五列展示「入口 → ACL → 路由 → 拨号计划/动作 → 目的地」，输入被叫号码与主叫 IP 可模拟 ACL 放行/拦截、命中路由与下一跳；节点右上角链接跳转对应编辑页，顶部「热生效」调用 `reloadxml`。ACL 规则按自上而下首条命中解释，与 FreeSWITCH 行为一致。

### 3.2 FS 参数配置页（设计重点）

**路径**：`/pbx/fsconf`  
**交互**：左侧配置段导航 + 右侧分组表单。

每个参数卡片包含：

| 展示元素 | 说明 |
|----------|------|
| 中文标题 | 给人看的名称 |
| 参数键 | 对应 FS `<param name="...">`，灰色小字 |
| 说明 | 完整作用描述 |
| 示例 | 推荐示例值 |
| 默认值 | 未配置时的默认 |
| 生效提示 | reloadxml / profile / docs 等 |
| 校验错误 | 标红 + 文案，滚动定位 |

**配置段示例**：

- `switch.conf` — RTP 端口、最大会话、日志级别  
- `sofia.conf/internal` — 分机 Profile  
- `sofia.conf/external` — 中继 Profile  
- `cdr_pg_csv.conf` — 话单库连接  
- `voicemail.conf` / `conference.conf`  
- `event_socket` — **仅说明**（真实 ESL 在 `fs.properties`）

**重要**：该页保存的是参数值到表 `t_pbx_fs_param`，**不会**去改 FreeSWITCH 安装目录下的 XML 文件。

### 3.3 校验规则（产品体验）

| 类型 | 前端 | 后端 |
|------|------|------|
| 必填 | 本地校验 | `FsConfigServiceImpl.validate` |
| 端口/整数范围 | min/max | 同左 |
| IP / 正则 / 枚举 | 同左 | 同左 |
| RTP 起止交叉 | start &lt; end | 同左 |
| 保存失败 | 按 `errors[]` 标红字段 | 返回 AjaxResult.errors |

按钮：

- **仅校验** — 不写库  
- **仅保存** — 写库不热生效  
- **保存并热生效** — 写库 + ESL

## 4. 关键概念（设计与开发共用词汇）

| 术语 | 含义 |
|------|------|
| directory | SIP 用户/域名目录，注册鉴权用 |
| dialplan | 拨号计划：匹配被叫后执行 answer/bridge/ivr 等 |
| sofia profile | SIP 协议栈实例，如 internal / external |
| gateway | 外线中继账号 |
| ESL | Event Socket Library，JPBX 连 FS 的控制通道 |
| xml_curl | FS 向 HTTP 服务拉取 XML 配置 |
| 热生效 | 不重启 FS 进程，用 API 让新配置立即参与新呼叫/新注册 |

## 5. 开发约定

### 5.1 代码放哪里

| 内容 | 路径 |
|------|------|
| Controller / Service / Domain / Mapper | `jpbx-gui/src/main/java/com/av/jpbx/**` |
| MyBatis XML | `jpbx-gui/src/main/resources/mapper/pbx/` |
| 页面 | `jpbx-gui/src/main/resources/templates/pbx/` |
| FS XML 模板（Velocity） | `jpbx-gui/src/main/resources/vm/xml/` |
| 参数元数据目录 | `com.av.jpbx.fsconf.FsParamCatalog` |
| ESL / 热生效 | `FsEslClient`、`FsApplyService` |
| xml_curl | `TPbxApiController` + `XmlCurlServiceImpl` |

### 5.2 新增一个业务菜单的标准步骤

1. 表结构写入 `sql/pbx_pgsql.sql`（并评估是否需要迁移 ALTER）  
2. Domain / Mapper / Service / Controller / 页面（可参考 `TPbxDomain*`）  
3. 若需下发给 FS：补 Velocity 模板 + `XmlCurlServiceImpl` 分支  
4. 写操作成功后调用 `fsApplyService.apply(FsResourceType.XXX)`  
5. 菜单 SQL + 权限标识 `pbx:xxx:view|list|add|edit|remove`  
6. 更新本文档功能表  

### 5.3 新增一个 FS 配置参数

1. 在 `FsParamCatalog` 对应段增加 `FsParamDef`（标题、说明、示例、类型、必填、正则、min/max、applyHint、group）  
2. 确认 `vm/xml/*.vm` 能读取 `params.get('key')`  
3. 前端 `/pbx/fsconf` **无需改页面**（元数据驱动自动渲染）  
4. 联调：保存 → 看 ESL → 用 `fs_cli` / 下一通呼叫验证  

### 5.4 命名与风格

- 包名：`com.av.jpbx`  
- 表名：`t_pbx_*`  
- 权限：`pbx:<资源>:<动作>`  
- UI：沿用 Bootstrap Table + `$.operate` / `$.table` / `$.validate`  
- 日志：业务用 `slf4j`，避免 `System.out`  

### 5.5 安全注意

- `/pbx/api/**` 对 Shiro 匿名（供 FS 回调），必须配置：  
  - `fs.properties` → `xmlCurlToken`  
  - 建议同时配置 `xmlCurlAllowedIps`  
- `/pbx/route/**` 已取消匿名，需登录  
- ESL 控制台禁止 `shutdown` 等危险命令（见 `TPbxOpsController`）

## 6. 环境与部署

### 6.1 依赖环境

- JDK 21  
- Maven 3.6+  
- PostgreSQL 12+（脚本按 PG 语法，含 `IF NOT EXISTS` / `ON CONFLICT`）  
- FreeSWITCH 1.11.0（或兼容的 1.10+/1.11 线）  

### 6.2 配置文件清单

| 文件 | 关键项 |
|------|--------|
| `application.yml` | 端口 8090、Thymeleaf、MyBatis |
| `application-druid.yml` | JDBC URL / 用户名密码 |
| `fs.properties` | `eslHost`、`eslInBoundPort`、`eslpwd`、`xmlCurlToken`、`xmlCurlAllowedIps` |

### 6.3 启动后自检

1. 日志出现 `ESL connected host:port`  
2. 登录后能打开「FS参数配置」「分机管理」  
3. FS `sofia status` 正常；注册后「注册列表」有数据  
4. 改一个分机密码 → 保存 → 重新注册成功（无需重启 FS）  

更完整的 FS 下载、安装与对接步骤见 [FreeSWITCH对接与安装说明.md](FreeSWITCH对接与安装说明.md)。

## 9. 常见问题

**Q: 改了配置为什么没生效？**  
A: 看是否点了「热生效」；看 ESL 是否连接；Sofia 参数是否需要 profile restart；下一通新呼叫才会拉新 dialplan。

**Q: 注册不走管理台密码？**  
A: sofia 必须 `accept-blind-reg=false`，且 directory 走 xml_curl。

**Q: 能否手改 FS 的 conf 文件？**  
A: 可以，但会被本地静态配置干扰动态配置。推荐精简本地 dialplan/directory，以 JPBX 为准。

**Q: 设计稿要体现哪些校验提示？**  
A: 必填星号、字段下灰色说明+蓝色示例、错误时红框+红字、保存失败汇总条数。
