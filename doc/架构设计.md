# JPBX 架构设计文档

> 面向：**架构师 / 后端开发 / 熟悉 FreeSWITCH 的实施人员**。  
> 产品与设计请先读 [项目说明.md](项目说明.md)。

---

## 1. 设计目标与约束

### 1.1 目标

1. 用 Web 完成 FreeSWITCH 1.11 的配置与运维闭环。  
2. **配置以数据为中心**：库表 / 参数键值 → xml_curl 生成 XML → FS 使用。  
3. **变更热生效**：禁止把「重启 FS」当作常规手段。  
4. 复用系统权限、菜单、组织能力，降低后台开发成本。

### 1.2 约束

| 约束 | 说明 |
|------|------|
| 技术栈 | JDK21 + Spring Boot 2.5 + Shiro + Thymeleaf + MyBatis + PostgreSQL |
| FS 集成 | ESL inbound + mod_xml_curl（主路径） |
| 兼容 | 保留旧「路由表」生成 bridge；逐步迁移到 dialplan 表 |
| 安全 | xml_curl 匿名接口必须 token/IP 防护 |

## 2. 逻辑架构

```
┌─────────────────────────────────────────────────────────────┐
│                     浏览器（管理员）                          │
│              Thymeleaf 页面 / Bootstrap Table                 │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP(S) :8090
┌───────────────────────────▼─────────────────────────────────┐
│                      av-admin（Web 入口）                     │
│  Shiro 鉴权 ──► Controller ──► Service ──► Mapper ──► PG     │
│                      │                                       │
│              FsApplyService / FsEslClient                     │
└───────────┬───────────────────────────────┬─────────────────┘
            │ ESL :8021                     │ xml_curl HTTP
            ▼                               ▼
┌───────────────────────┐     ┌───────────────────────────────┐
│   FreeSWITCH 1.11     │◄────│  /pbx/api/xml                 │
│  sofia / dialplan /   │     │  XmlCurlServiceImpl           │
│  callcenter / ...     │     │  Velocity → XML               │
└───────────────────────┘     └───────────────────────────────┘
```

### 2.1 三条主链路

| 链路 | 方向 | 作用 |
|------|------|------|
| 管理链路 | 人 → JPBX → DB | CRUD 业务与参数 |
| 控制链路 | JPBX → ESL → FS | 热生效、运维命令、事件监听 |
| 配置链路 | FS → xml_curl → JPBX | 按需拉取 directory / dialplan / configuration |

## 5. 配置下发架构（xml_curl）

### 5.1 请求入口

- 统一：`GET|POST /pbx/api/xml`  
- 兼容：`/pbx/api/user/getUserXML`、`/pbx/api/conf/getXML`  
- 控制器：`TPbxApiController`  
- 编排：`XmlCurlServiceImpl.resolve(params)`

### 5.2 section 路由

| section | 关键参数 | 输出 |
|---------|----------|------|
| `directory` | user / domain | `user.xml.vm` |
| `dialplan` | Hunt-Context / Caller-Context | `dialplan.xml.vm` |
| `configuration` | key_value / profile | sofia / switch / acl / cdr / ivr / callcenter / conference / voicemail |

空配置返回标准 not-found 文档（`FsXmlTemplate.notFound()`），避免 FS 解析失败。

### 5.3 参数优先策略

对于 sofia / switch / cdr 等：

1. 优先读 `t_pbx_fs_param`（`IFsConfigService.resolveValues`）  
2. 回退 `t_pbx_sysconf` 或模板默认值  
3. Velocity 中通过 `$params.get('sip-port')` 取值  

**结论：管理台改的是参数与业务数据，不是 FS 文件系统。**

### 5.4 鉴权

`FSConfigure`：

- `xmlCurlToken`：请求参数 `token` 或头 `X-FS-Token`  
- `xmlCurlAllowedIps`：来源 IP 白名单  

逻辑：token 不匹配时，仅当白名单配置且命中才放行。

## 6. ESL 与热生效

### 6.1 连接管理

| 类 | 职责 |
|----|------|
| `FsEslClient` | 连接、重连、`sendApi`、持有最新 sysconf |
| `EslListenerServer` | 启动门面；可选 outbound（默认关闭） |
| `Fs2Sever` | `CommandLineRunner`，启动连接 + 60s keepalive |
| `EslEventServiceImpl` | 事件监听（注册/挂断等日志与扩展点），**不做拨号** |

### 6.2 FsApplyService 映射

| FsResourceType | 典型 ESL |
|----------------|----------|
| DIRECTORY / DIALPLAN / IVR / VOICEMAIL / CONFERENCE / RELOAD_XML | `reloadxml` |
| GATEWAY | `reloadxml` + `sofia profile {p} killgw` + `rescan` |
| SOFIA_PROFILE | `reloadxml` + `sofia profile {p} restart` |
| ACL | `reloadxml` + `reloadacl` |
| CALLCENTER | `reloadxml` + queue load/unload 或 `reload mod_callcenter` |
| MODULE | `load` / `unload` / `reload` |
| SYSCONF | `reloadxml` + 各 sofia profile restart |

最近一次结果缓存在内存，运维页可查询。

### 6.3 为何「profile restart ≠ FS 重启」

Sofia profile restart 只重建该 SIP Profile 的监听与网关状态；核心进程、其他模块、已建立媒体会话策略按 FS 自身行为处理。新注册/新呼叫使用新配置。完整进程重启仅用于文档中列出的例外项。

## 7. 领域模型关系

```
t_pbx_domain 1──* t_pbx_user
t_pbx_group  1──* t_pbx_group_user ──► user_number

t_pbx_dialplan 1──* t_pbx_dialplan_action
t_pbx_route    1──* t_pbx_change_number     （兼容旧模型）

t_pbx_gateway  ──► 挂入 sofia external XML

t_pbx_ivr 1──* t_pbx_ivr_entry
t_pbx_queue / t_pbx_agent / t_pbx_tier
t_pbx_conference / t_pbx_conference_profile

t_pbx_fs_param (section, param_key) UNIQUE
t_pbx_sysconf  （单例式系统级路径/IP 等）
cdr            （mod_cdr_pg_csv）
```

### 7.1 dialplan 生成逻辑（XmlCurlServiceImpl）

1. 加载 `t_pbx_dialplan` + actions（enabled、按 sort_order）  
2. 叠加兼容路由 `t_pbx_route`（按 context/type 过滤）  
3. 自动生成本地分机互拨（用户号码 OR 正则）  
4. 叠加 conference / queue / ivr 入口扩展  
5. 渲染 `dialplan.xml.vm`

## 8. FS 参数配置子系统

```
FsConfigSection（段枚举）
    └── FsParamCatalog（元数据：说明/示例/校验）
            └── t_pbx_fs_param（运行时值）
                    └── XmlCurl / Velocity
```

| 类 | 作用 |
|----|------|
| `FsParamDef` | 单参数元数据 |
| `FsParamCatalog` | 静态目录（扩展点） |
| `FsConfigServiceImpl` | 校验、upsert、触发 apply |
| `TPbxFsConfigController` | `/pbx/fsconf` API + 页 |

扩展新参数：**只改 Catalog + 必要时改 vm**，页面自动渲染。

## 9. 前端架构（业务页）

- 服务端渲染：Thymeleaf  
- 列表：Bootstrap Table（`$.table.init`）  
- 表单：`$.validate` + `$.operate.save`  
- 权限：`shiro:hasPermission`  
- FS 参数页：单页 SPA 风格（左侧导航 + AJAX 拉元数据），见 `templates/pbx/fsconf/fsconf.html`

设计约束：

- 字段必须有说明与示例（参数页由元数据保证）  
- 错误必须绑定到具体 `param key`  
- 危险运维操作需确认框（挂断通道等）

## 10. 安全架构

```
浏览器 ──Shiro──► /pbx/* 业务接口（需登录 + 权限）
FS     ──anon──► /pbx/api/** （token / IP）
```

| 点 | 实现 |
|----|------|
| 登录会话 | Shiro + OnlineSession |
| 接口权限 | `@RequiresPermissions` |
| xml_curl | token + 可选 IP 白名单 |
| ESL 控制台 | 命令黑名单（shutdown 等） |
| 录音下载 | 路径规范化，禁止目录穿越 |

## 11. 部署拓扑建议

```
          ┌────────────┐
  SIP/RTP │ FreeSWITCH │◄──── ESL 8021 ────┐
          └─────▲──────┘                   │
                │ xml_curl                 │
                │                          │
          ┌─────┴──────┐            ┌──────┴──────┐
          │   JPBX     │───────────►│ PostgreSQL  │
          │  :8090     │            │  youpbx     │
          └────────────┘            └─────────────┘
```

- JPBX 与 FS 网络互通：8090（curl）、8021（ESL）  
- 录音/日志路径：FS 与 JPBX 可见（同机或共享存储）  
- 生产将 DB/ESL 口令外置，限制 xml_curl 来源 IP

## 12. 关键时序

### 12.1 保存 Sofia 参数并热生效

```
Admin → POST /pbx/fsconf/save
     → FsConfigService.validate
     → upsert t_pbx_fs_param
     → FsApplyService(SOFIA_PROFILE)
     → ESL: reloadxml
     → ESL: sofia profile internal restart
Admin ← 成功 / errors[]
```

### 12.2 分机注册

```
Phone → REGISTER → FS
FS → GET /pbx/api/xml?section=directory&user=1001
JPBX → 查 t_pbx_user → user.xml.vm → XML
FS → Digest 鉴权 → 200 OK
```

### 12.3 呼叫

```
Phone → INVITE → FS
FS → xml_curl section=dialplan&Hunt-Context=default
JPBX → dialplan.xml.vm
FS → 执行 bridge / ivr / callcenter / ...
FS → CDR → PostgreSQL.cdr
```

## 15. 架构决策记录（ADR 摘要）

| 决策 | 选择 | 原因 |
|------|------|------|
| 拨号执行位置 | FS dialplan，非 ESL originate | 标准、可扩展 IVR/队列/会议 |
| 配置存储 | DB + 参数表 | 可审计、可校验、多节点一致 |
| 下发方式 | xml_curl | 与 FS 原生集成，免 NFS 改文件 |
| 生效方式 | ESL 热加载 | 满足「不重启 FS」约束 |
| UI 框架 | Thymeleaf + Bootstrap 3 + 主题层 | 成本低，与现有权限一体 |
| 参数 UI | 元数据驱动 | 说明/示例/校验统一，设计与开发同源 |
